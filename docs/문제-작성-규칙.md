# 문제 작성 규칙

「⑤ 문제 풀기」 탭의 문제 은행(`quiz/<열쇠>.json`)을 쓰는 규칙이다.
문제를 새로 쓰거나 고칠 때 이 문서를 먼저 읽는다.

## 0. 가장 중요한 규칙 — 독자적으로 쓴다

- **이 폴더(`ml-lab/`) 밖의 파일을 열지 않는다.** 다른 앱이나 자료의 문제를 참고하지 않는다.
- 시중 문제집·시험 대비 자료·강의 노트북에서 본 문제를 떠올려 옮기지 않는다.
- 문제의 출발점은 오직 세 가지다.
  ① 이 앱의 데이터(`data/`)와 그 설계 의도(`tools/make_data.py` 주석, 아래 회차별 목표)
  ② 머신러닝 개념 그 자체(교과서 수준의 일반 지식)
  ③ pandas · scikit-learn 공식 사용법
- 회차마다 같은 틀(불러오기 → 시각화 → 결측치 → … → 예측)을 되풀이하지 않는다.
  **그 회차 데이터에만 있는 가르칠 거리**를 중심에 두고, 흔한 단계는 필요한 만큼만 넣는다.

## 1. 파일 모양

`quiz/<열쇠>.json` 하나가 한 회차다. UTF-8, 들여쓰기 2칸.

```json
{
  "goal": "이 회차에서 배우는 것을 한 문장으로",
  "setup": "import pandas as pd\nexam_df = pd.read_csv('exam_result.csv')",
  "problems": [ { … }, { … } ]
}
```

- `setup` — 회차의 모든 문제보다 먼저 실행되는 코드. 화면에 「먼저 실행해 두는 코드」로 보인다.
  데이터를 불러오는 줄은 여기 두어도 되고, 첫 문제로 내도 된다.
- 문제는 **8~10개**. 차례대로 실행되며 앞 문제가 만든 변수를 뒤 문제가 이어 쓴다
  (한 회차가 하나의 노트북처럼 이어진다).

### 모든 문제에 공통

| 칸 | 필수 | 설명 |
|---|---|---|
| `id` | ✓ | `<열쇠>-<두 자리 번호>` (예: `exam-03`). 회차 안에서 겹치지 않게 |
| `type` | ✓ | `blank` · `choice` · `bug` · `order` |
| `stage` | ✓ | `살펴보기` `시각화` `결측치` `인코딩` `파생변수` `분리·스케일링` `모델 학습` `평가` `딥러닝` `해석·예측` 중 하나 |
| `title` | ✓ | 짧은 제목 (20자 안팎) |
| `prompt` | ✓ | 지문. 간단한 마크다운(`**굵게**`, `` `코드` ``, `* 목록`) |
| `explain` | ✓ | 해설. **「왜」를 설명**한다. 정답만 되풀이하지 말 것. 40자 이상 |
| `hint` |  | 힌트 한 줄. 빈칸은 없으면 첫 글자 힌트가 자동으로 나온다 |
| `lab` |  | `{"tab": "explore"|"prep"|"train"|"deep", "say": "…"}` — 같은 데이터로 그 탭을 여는 단추 |
| `check` |  | 파이썬 식 목록. 이 문제의 코드를 실행한 뒤 모두 `True` 여야 한다 (아래 3절) |
| `run` |  | `false` 면 실행하지 않고 문법만 본다 (keras 코드에만 쓴다) |
| `sandbox` |  | `true` 면 이 문제의 코드가 만든 변수를 다음 문제로 넘기지 않는다 |

### `blank` — 빈칸 채우기

```json
{
  "type": "blank",
  "code": "X_train, X_valid, y_train, y_valid = ⟦train_test_split⟧(\n    X, y, test_size=⟦0.25⟧, random_state=7)",
  "blanks": [
    {"options": ["KFold", "cross_val_score", "StratifiedKFold"]},
    {"options": []}
  ]
}
```

- 빈칸은 `⟦정답⟧` 으로 적는다. **대괄호 `[[ ]]` 가 아니다** — 파이썬의 `df[['a','b']]` 와 헷갈리기 때문이다.
  `⟦` 는 U+27E6, `⟧` 는 U+27E7.
- `blanks` 는 빈칸 개수와 같은 길이. `options` 는 **오답만** 적는다(정답은 화면이 섞어 넣는다).
  오답은 2~4개, 서로 겹치지 않고 정답과도 다르다. 그럴듯한 오답일수록 좋다.
- `options` 가 빈 목록이면 학생이 직접 입력한다 — 데이터를 봐야 알 수 있는 값(개수·이름)에 쓴다.
- 한 문제의 빈칸은 1~3개. 문법 외우기가 아니라 **개념을 가르는 자리**를 비운다
  (`fit_transform` ↔ `transform`, `stratify=y`, `test_size` 처럼).

### `choice` — 고르기

```json
{
  "type": "choice",
  "code": "print(exam_df['club_join'].isna().sum())",
  "choices": ["0", "45", "51", "1150"],
  "answer": 2
}
```

- `choices` 3~5개, `answer` 는 **0부터 센** 정답 자리. `code` 는 없어도 된다.
- 실행 결과를 묻는 문제는 반드시 `check` 로 그 값을 확인한다.
- 정답 자리가 한쪽(예: 늘 ②)에 몰리지 않게 회차 안에서 고르게 둔다.

### `bug` — 오류 찾기

```json
{
  "type": "bug",
  "code": "scaler = StandardScaler()\nX_train_s = scaler.fit_transform(X_train)\nX_valid_s = scaler.fit_transform(X_valid)",
  "answer": 3,
  "fix": "X_valid_s = scaler.transform(X_valid)"
}
```

- `answer` 는 **1부터 센** 잘못된 줄 번호, `fix` 는 그 줄을 바로잡은 한 줄.
- 파이썬 점검은 `fix` 로 바꾼 코드를 실행한다.
- 오류는 **개념 실수**여야 한다 — 오타 찾기가 아니라 데이터 누수, 검증 데이터로 학습,
  `transform` 과 `fit_transform` 혼동, 목표 컬럼을 X 에 남김, 불균형인데 정확도만 봄 같은 것.

### `order` — 순서 맞추기

```json
{
  "type": "order",
  "steps": ["데이터를 불러온다", "훈련·검증으로 나눈다", "훈련 데이터로 스케일러를 학습한다", "모델을 학습한다"]
}
```

- `steps` 는 **올바른 차례대로** 3~6개. 화면이 섞어서 보여 준다.
- 순서가 뒤바뀌어도 되는 단계를 넣지 않는다(정답이 하나여야 한다).

## 2. 코드 규칙

- **pandas 2.2(코랩)와 pandas 3 에서 똑같이 돌아가야 한다.**
  - `inplace=True` 를 쓰지 않는다. `df['c'] = df['c'].fillna(v)` 처럼 다시 넣는다.
  - `df['c'].fillna(v, inplace=True)` 같은 연쇄 대입은 pandas 3 에서 원본을 바꾸지 않는다.
  - 글자 컬럼의 자료형은 pandas 2 에서 `object`, pandas 3 에서 `str` 로 찍힌다.
    이 이름을 정답으로 묻지 않는다. 「숫자가 아닌 자료형」처럼 묻는다.
- `random_state` 는 회차마다 우리가 정한 값을 쓴다(아무 값이나 괜찮지만 회차 안에서는 같게).
- 파일은 `pd.read_csv('exam_result.csv')` 처럼 **파일 이름만** 적는다(경로 없이).
- 변수 이름은 `meta.js` 의 `df` 이름(`exam_df`, `farm_df`…)을 따른다.
- 그래프는 seaborn/matplotlib 로 그려도 되지만, 점검에서는 그리지 않고 넘어간다.
  그래프를 보고 답하는 문제는 그 답을 **pandas 로 계산해** `check` 로 확인한다.
- keras 코드는 점검 PC 에 tensorflow 가 없어 실행하지 못한다. `"run": false` 로 두고,
  한 회차에 1~2문제까지만 쓴다(회귀 한 회차, 분류 한 회차 정도).

## 3. `check` — 정답이 데이터와 맞는지 확인

- 파이썬 식의 목록이다. 그 문제까지 실행한 상태에서 하나씩 `eval` 해 모두 `True` 여야 한다.
- 숫자는 반올림해서 비교한다: `"round(r2_score(y_valid, pred), 2) == 0.79"`.
- **지문·보기·해설에 적은 숫자는 전부 `check` 로 확인한다.** 손으로 짐작해 적지 않는다.
- 점검 명령: `python tools/verify_quiz.py` (특정 회차만: `python tools/verify_quiz.py exam`)
  `--show` 를 붙이면 문제마다 출력(print)을 보여 준다.

## 4. 글쓰기

- 지문은 「~하세요」, 해설은 「~입니다」.
- 문제 한 개가 한 가지를 묻는다. 지문에 불필요한 이야기를 늘어놓지 않는다.
- 회차 배경 이야기의 학교·회사·지명은 지어낸 것이다(`meta.js` 의 `background`). 실제 기관 이름을 쓰지 않는다.
- 자격증·시험·상표 이름을 쓰지 않는다.

## 5. 회차별 목표 — 이 회차에만 있는 가르칠 거리

각 회차 문제의 절반 이상이 아래 「중심」을 다뤄야 한다.
숫자는 `data/` 에서 확인한 값이지만, 문제에 쓰기 전에 반드시 다시 계산해 `check` 로 확인한다.

| 회차 | 열쇠 | 중심 | 데이터에서 확인한 사실 |
|---|---|---|---|
| 1 | `exam` | **머신러닝 한 바퀴** — 불러오기 · X/y 나누기 · 훈련/검증 분리 · 선형 회귀 · 평가를 처음으로 끝까지 | 1150행. 결측 midterm_point 45 · club_join 51. 목표와 상관 midterm 0.82 · study 0.70 · online_lecture 0.01. 있음/없음 컬럼 2개 |
| 2 | `crop` | **변수가 목표에 주는 영향 읽기** — 상관, 범주별 평균(groupby), 파생변수 만들기와 효과 확인, 특성 중요도 | 870행. 결측 mean_temp 25 · sun_hours 34. 강수량 상관 0.69. 흙 종류별 수확량 층. n/p/k 는 거의 무관 |
| 3 | `car` | **다중공선성과 원-핫 인코딩** — 상관 히트맵에서 붙어 다니는 짝 찾기, 범주 4개 원-핫, 선형 모델 계수 해석이 흔들리는 까닭, 트리는 덜 흔들림 | 960행. used_years↔total_distance_km, displacement_cc↔max_power_ps 짝. 목표와 used_years −0.86. 범주 결측 4컬럼 |
| 4 | `ad` | **치우친 목표와 규제** — 음수가 섞인 목표, 평균 대신 중앙값, 노출→클릭→가입 사슬의 공선성, 파생변수 클릭률, 릿지·라쏘 | 480행(작다). 결측 budget 17 · run_days 24. 목표와 signup 0.64 · click 0.49 · views 0.30 |
| 5 | `pay` | **순서형 인코딩** — 학력·직급·외국어는 순서 매핑, 부서는 원-핫. 레이블 인코더가 가나다순으로 번호를 매기는 함정, 스케일링과 계수 비교 | 770행. 결측 6컬럼. career_years 상관 0.92 |
| 6 | `yield` | **예측이 안 되는 데이터** — 상관이 모두 약함, 평균만 찍는 기준 모델과 비교, R² 가 0 근처·음수의 뜻, 과소적합과 「신호가 없음」 구별, 교차검증 | 1920행. 가장 센 상관 worker_years 0.29, 나머지 ≈0. 결측 4컬럼 |
| 7 | `home` | **두 파일 합치기와 결측이 많은 데이터** — merge(열쇠 home_id), 결측 7컬럼, dropna 하면 몇 행이 사라지나, 채우기 전략 비교, 트리 깊이와 과적합 | 두 파일 각 1440행 → 합쳐 12열. dropna 하면 1177행. 면적↔방 개수 공선성 |
| 8 | `churn` | **분류 입문과 더러운 숫자** — 숫자 컬럼에 섞인 글자(`to_numeric(errors='coerce')`), 클래스 비율, 로지스틱 회귀, 정확도·혼동 행렬, stratify | 2400행. 이탈 53.0%. total_paid_won 에 '-'·'미확인' 섞임. 결측 9컬럼 |
| 9 | `loan` | **살짝 불균형한 분류** — 「전부 승인」 기준선 정확도, 정밀도·재현율·F1 이 따로 필요한 까닭, 무엇을 놓치면 더 아픈가 | 1720행. 승인 90.8%. credit_point 0.25 · debt_ratio −0.22 |
| 10 | `quality` | **극단적 불균형과 임계값** — 정확도의 함정(99%), 재현율, `predict_proba` 와 임계값 낮추기, ROC-AUC, `class_weight` | 2880행. 불량 29건(1.01%). temp_c 0.18. 결측 worker_years 93 · work_min 81 |

- 딥러닝(keras) 문제는 `home`(회귀)과 `churn`(분류)에 1~2문제씩만 둔다.
- 앱의 실험실과 이어 주는 `lab` 을 회차마다 1개 이상 둔다
  (예: 「모델 학습실에서 결정 트리 깊이를 3 → 15 로 올려 훈련·검증 점수가 어떻게 갈라지는지 보자」).
  `lab` 문제의 정답은 앱 결과가 아니라 **개념**으로 정해지게 쓴다(앱과 파이썬의 숫자는 조금 다르다).

## 6. 문제 모양 섞기

- 한 회차에 네 가지 모양 중 **세 가지 이상**을 쓴다.
- `blank` 는 회차 문제의 절반을 넘지 않는다.
- `bug` 는 회차마다 1개 이상.
